# 1. PROJECT FOUNDATION

## Understand Before Building

AI agents must never immediately code from vague instructions.

Before implementation:

-   Understand the product mission.
-   Study existing architecture.
-   Identify affected files.
-   Identify risks.
-   Create a plan.

The goal is not just writing code. The goal is building a reliable
product.

------------------------------------------------------------------------

# 2. AI AGENT CONSTITUTION

## Rule 1: Protect Existing Systems

Never break working features.

Before modifying:

-   inspect current files
-   understand dependencies
-   check APIs
-   check database relationships
-   verify authentication flows

Prefer additive changes over destructive rewrites.

------------------------------------------------------------------------

## Rule 2: Plan Before Coding

Required workflow:

Requirement → Analysis → Plan → Implementation → Testing → Checkpoint

No blind execution.

------------------------------------------------------------------------

## Rule 3: No Prototype Behaviour

Never create:

-   fake analytics
-   random numbers
-   mock dashboards
-   temporary shortcuts

If data does not exist, create proper empty states.

------------------------------------------------------------------------

# 3. CHECKPOINT DEVELOPMENT

Large applications must be developed in versions.

Example:

V1.0 Foundation

V1.1 Authentication

V1.2 Core Product

V1.3 Dashboard

V1.4 AI Features

V1.5 Analytics

V1.6 UI Polish

V1.7 Production Hardening

Every checkpoint requires:

-   testing
-   documentation
-   Git commit
-   review

------------------------------------------------------------------------

# 4. ARCHITECTURE RULES

Recommended structure:

src/ - app: routes and pages - components: reusable UI - services:
business logic - actions: server actions - lib: utilities - hooks:
reusable logic - types: shared types

Every file must have a clear responsibility.

------------------------------------------------------------------------

# 5. DATABASE CONSTITUTION

Database changes require:

1.  Migration file
2.  Schema review
3.  Security review
4.  Testing

Never manually change production databases.

Validate:

-   ownership
-   permissions
-   relationships
-   input data

------------------------------------------------------------------------

# 6. AI INTEGRATION RULES

Never expose:

-   API keys
-   secrets
-   credentials

Correct architecture:

Frontend ↓ Secure API Route ↓ AI Service ↓ Database

AI output must always be validated.

------------------------------------------------------------------------

# 7. UI/UX DESIGN SYSTEM

Applications must feel:

-   premium
-   consistent
-   simple
-   professional

Avoid:

-   random colors
-   inconsistent spacing
-   default browser styling
-   unnecessary complexity

Reuse existing components before creating new ones.

------------------------------------------------------------------------

# 8. MOBILE FIRST RULES

Every screen must support:

-   mobile phones
-   tablets
-   desktop

Rules:

-   44px minimum touch targets
-   48px minimum button height
-   no horizontal overflow
-   responsive layouts
-   mobile testing required

------------------------------------------------------------------------

# 9. DATA RULES

Production applications must use real data.

Never display fabricated:

-   users
-   analytics
-   statistics
-   results

When no data exists:

Show:

-   empty state
-   explanation
-   next action

# 11. AI AGENT PROMPT TEMPLATE

You are working on a production application.

Before coding:

1.  Analyze existing architecture.
2.  Create an implementation plan.
3.  List affected files.
4.  Explain risks.

During coding:

-   Do not create mock data.
-   Do not modify unrelated systems.
-   Do not break existing functionality.
-   Follow the design system.

After coding:

Provide:

-   files changed
-   tests completed
-   known limitations
-   checkpoint summary

# 12. QUALITY ASSURANCE

Before completion:

Code:

✓ TypeScript passes\
✓ Build passes\
✓ No console errors\
✓ No unused imports

Product:

✓ User flow works\
✓ Mobile responsive\
✓ Desktop responsive\
✓ Error states exist

Security:

✓ Secrets protected\
✓ Permissions checked\
✓ Inputs validated

------------------------------------------------------------------------

# 13. PRODUCTIVITY PRINCIPLES

Build faster by:

-   creating reusable components
-   using templates
-   working in checkpoints
-   documenting decisions
-   avoiding unnecessary rewrites

Avoid:

-   changing everything at once
-   vague prompts
-   uncontrolled AI changes

------------------------------------------------------------------------

# 14. DOCUMENTATION SYSTEM

Every project should maintain:

-   Architecture documentation
-   Database documentation
-   Feature plans
-   Checkpoint reports
-   Change logs

Documentation is part of engineering.

------------------------------------------------------------------------

# 15. FINAL COMMANDMENTS

1.  Understand before coding.
2.  Protect existing functionality.
3.  Never invent data.
4.  Never expose secrets.
5.  Plan every feature.
6.  Build incrementally.
7.  Respect design systems.
8.  Test everything.
9.  Document decisions.
10. Build for real users.

------------------------------------------------------------------------

# PRODUCTION READY DEFINITION

A feature is complete only when:

-   It solves the user problem.
-   It works technically.
-   It is secure.
-   It is responsive.
-   It is tested.
-   It is documented.

This constitution defines the collaboration rules between human
developers and AI coding agents.
